  THE DEAD END  (found when the user reported "most things don't work")

  connect() bailed on `!doc.chain`, and stageEvent() always staged. An empty
  document therefore had no event in the chain, and connect() only ever
  extends from an event already in the chain — so a NEW PIPELINE COULD NEVER
  ACQUIRE ITS FIRST EVENT. Every gesture after that appeared broken because
  everything downstream depends on the chain existing.

  Compounding it: store.notice was never rendered anywhere. Every refusal —
  and the model refuses a lot, on purpose, with the Pointy rule attached —
  was silent. Silent refusal is indistinguishable from a broken button.

  Fixed:
    - stageEvent: the FIRST event becomes the chain. One event is a valid
      Pointy program; staging it was a trap.
    - connect: a wire between two staged events seeds an empty chain.
    - connect: a backwards wire now says so, naming the direction, instead of
      "Connect the source into the pipeline first."
    - Notice component over the canvas; 7s, dismissable.

== TRAPS — re-read before touching the model ==                              §12

  Descriptors are ints 0-9 BY DESIGN. process() returns (bool, result) — the
  second value is the result, not a descriptor. Explicit branching is
  self.goto(n, ok, result). An earlier design pass got this backwards.

  @mode: "CFG" is the DEFAULT and is how loops/retries/handoffs are expressed.
  The language has no loop keyword. DAG is the strict opt-in.

  |-> is a STREAMING pipe — memory-bounded, downstream starts before upstream
  ends. Not "pipe the result".

  local:: is implicit and must never be written into the output.

  Node position carries NO meaning. If you are sorting nodes by x to build the
  chain, stop — that is the bug §4 exists to prevent.
